   ## Description

    This program is my first own project: you can track and analyse your menstruation cycle.
    In the main function the user is greeted by a welcome message. There is a special classmethod "Greetings" for welcome, goodbye, track and analyse using pyfiglet for ascii art font. The font can be changed in the create_figlet() function. The user is then prompted (inside a while loop) if they want to track, analyse or exit the program. To validate the input there is a validatetion function implemented that uses regex, as I found this to be a good and flexible way to work with user input and error handling. If the input is not according, the user will be informed about the invalid input and reprompted.
    If the input is valid we have three if/elif-pathes: The first choice for tracking - here the track_and_save() function is implemented. For tracking I created a seperated class in order to keep track of the methods all together and I also thought it was the best way to store data and keep everything together. We create an object by calling Track(), which has a str-function implemented that explains the scaling of the data about the cycle that will be inputted. The get_date() method has a special purpose: It will check if there is already data for the date of today (implemented with date.time), and will read in the csv-file (where data will be stored) if this date already exists. It is done by using csv dictionary reader. If the date doesnt exist yet, the date will be saved, if the data exists - the user can choose between overwriting (here I had to use lists and loops to extract the data and remove the existing data of today) and going back to main menu option of tracking, analyzing or exiting. If data doesnt exists for today or is overwritten, we go to the next step of getting data for bleeding, physical wellbeing, pain, mood, physical activity and stress. As the data is collected by a scale 0-10 - the input will be validated. The user also has the option of typing "Q" at any time to quit the program. After inputting data the user is asked if they want to save data.
    The save method is using csv Dictwriter and class-defined fieldnames to save the data. If user doesnt want to save data, it will not be transfered to csv file and user will be reprompted between options of analyzing, tracking or qutting program.
    If the path of analysis will be chosen. The classmethod of read_and_analyse is implemented. Since the project and starting to learn pandas took longer than anticipated, I only made a quite "simple" analysis tool that just outputs some of the possible data analysis at once. I use pandas library to read csv file and to create a dataFrame and fill the mising dates if there was days where no data was inputted. Since I had to track each cycle (named: cycle_id) I had to implement day-one of a cycle, which I did by the data of bleeding and they day before the bleeding (shift-method). Then I counted the days from 1 till end of one cycle in cycle_day. I filtered out the unfinished cycles to calculate the average length of the cycle and then created min and max data by the categories by sorting them and put them together with cycle day and bleeding amount. I used tabulate to make the data more visually appealing. Analysis could be improved in the future but for now for this project I chose to stop here.
